# 简历撰写

从用户的真实材料出发写一份能过筛选的中文简历。核心约束：内容必须真实，表达必须具体。

## 输入

按优先级找材料，不要让用户从零口述：

1. 材料文件夹里的 `registration-profile.yaml` 资料包（browser-form-registration 生成的）
2. 现有简历（旧版也行，作为事实底稿）
3. 成绩单、获奖证书、项目文档等散件
4. 都没有时才按资料包模板的分组逐项问

目标岗位 JD 有就要过来，定制版和通用版的写法差别很大。

## 内容原则

- **真实红线**：不编造经历、职位、时间段、数据。材料里没有的量化数字，先问用户"这个项目大概服务多少用户/提升了多少"，用户给的数字才能写；用户说不清就用定性描述，不虚构。
- 每段经历用"动词开头 + 做了什么 + 结果"的结构，尽量带数字：不写"负责后端开发"，写"重写订单查询接口，响应时间从 800ms 降到 120ms"。
- 删掉不传递信息的词：吃苦耐劳、责任心强、精通（除非真精通）、熟练掌握office。技能按真实水平分层写：精通 / 熟悉 / 了解。
- 篇幅：应届生一页，五年以上经验最多两页。删不掉就砍最早、最不相关的经历。
- 写得像人：句子长短交替，不用"首先/其次/最后"式八股连接，不写"综上所述"式套话。

## 结构与顺序

- 应届生：基本信息 → 求职意向 → 教育背景（含 GPA/排名，好看才写）→ 实习经历 → 项目经历 → 技能证书 → 荣誉奖项
- 社招：基本信息 → 求职意向 → 工作经历（倒序）→ 项目经历 → 教育背景 → 技能证书
- 基本信息只留：姓名、电话、邮箱、城市、（技术岗）GitHub/作品链接。政治面貌、婚育、籍贯只在目标单位需要时加（国企、事业编）。
- 照片：投国企、银行、公务员类带证件照，互联网公司可不带。

## JD 定制

拿到 JD 时先做匹配度分析给用户看：

1. JD 的硬性要求逐条对照：学历、经验年限、必备技能——命中的、勉强的、缺失的各列一栏。
2. 缺失项如果致命（如必须 3 年经验而用户应届），直说建议斟酌投递，不粉饰。
3. 定制动作：把命中 JD 关键词的经历提到该段最前面，措辞向 JD 的用词靠拢（对方写"微服务"就不写"分布式服务拆分"），删减无关经历的篇幅。只调整表达和详略，不改事实。

## 输出

- 默认输出 `.docx`（优先用 `python-docx` / `pandoc` 或内置 `docx` skill 生成），方便用户后续自己微调；用户要 PDF 再转。
- 排版克制：单栏、黑白灰、字体不超过两种、对齐一致、日期格式统一（2024.07-2026.06）。花哨模板过不了机器筛选也不讨 HR 喜欢。
- 命名：`姓名_岗位_公司.docx`，通用版 `姓名_简历_通用版.docx`。
- 存在材料文件夹的 `简历版本/` 子目录，一次投递一个定制版，别覆盖通用版。

## 交付前自检

对照 [references/checklist.md](references/checklist.md) 过一遍，把发现的问题修掉再交给用户，同时把不确定的点（待确认的数字、时间线空档）列出来。
