# Boss直聘求职代办

在用户已登录的浏览器里操作 Boss直聘，帮用户完成搜索、筛选、打招呼投递和消息回复。所有对外发送的内容先经用户确认，操作节奏保持像人。

## 前提

- **Claude Code**：使用 Claude in Chrome 扩展（`mcp__claude-in-chrome__*` 工具，`read_page` 读页面）直接操作用户的真实 Chrome。
- **Codex / Cursor / Antigravity**：使用 Playwright MCP（`browser_snapshot` 读页面），推荐 extension 模式连接用户真实 Chrome（`--extension` 参数 + Playwright MCP Bridge 扩展，配置见 [docs/BROWSER_MCP_SETUP.md](../../../docs/BROWSER_MCP_SETUP.md)）；也可以用默认模式的持久化档案。
- 开始前打开 zhipin.com 确认登录状态。未登录就请用户自己登录（密码、短信验证码、扫码都由用户本人完成），登录好了再继续。
- 出现滑块或图片验证码时交还用户，不要尝试绕过。

## 第一步：求职画像

投递前先明确，问一次记下来（建议存到材料文件夹的 `job-preferences.yaml`，下次直接读）：

- 目标岗位关键词（2-3 个变体，如"后端开发 / Java 开发 / 服务端开发"）
- 城市、通勤范围
- 薪资底线
- 排除项：不投的公司、行业、外包与否、规模要求
- 在线简历是否已在 Boss直聘上传并为最新版（没有就先提醒用户去更新，打招呼后招聘者看到的是平台在线简历）

有 browser-form-registration 的资料包或简历文件时先读，画像里的经历技能从那里取，不要让用户重复口述。

## 第二步：搜索与筛选（两轮）

**第一轮，列表页粗筛**：

1. 按画像在网站上设置搜索词和筛选条件（城市、薪资、经验、学历）。
2. `browser_snapshot` 解析职位列表，翻页收集候选，每个记录：岗位、公司、薪资、经验学历要求、职位链接。
3. 只剔除硬伤：薪资低于底线、经验学历要求明显够不上、命中排除项、台账里已投过的。拿不准的留到第二轮，列表页信息太少，不在这一轮下匹配结论。

**第二轮，逐个点开详情页细看**：

4. 对粗筛后的每个候选，点开职位详情页，读完整内容：岗位职责、任职要求全文、公司介绍、规模与融资阶段、招聘者活跃度（"刚刚活跃"还是"半年前活跃"，后者基本不用投）。
5. 拿 JD 的任职要求跟用户的简历/资料包**逐条核对**：学历、经验年限、必备技能、加分项，每条标"符合 / 勉强 / 缺失"。职责描述再对照用户做过的事，判断进去能不能接得住。
6. 点开详情也保持人类节奏，每个间隔几秒；一轮细看控制在 30 个以内，多了分批。
7. 给用户一张候选清单，按匹配度排序，每条含：岗位 / 公司 / 薪资 / 招聘者活跃度 / 硬性要求逐条核对结果 / 顾虑（如接受出差、大小周）/ 链接。让用户扫一眼就能自己判断"这个和我符不符"，而不是只看一个分数。

## 第三步：批量打招呼投递

用户从清单里圈定要投的岗位后，这一批视为已授权，逐个执行：

1. 打开职位详情页，核对与第二轮细看时一致（薪资缩水、要求变更、职位已下线就跳过并记录）。
2. 点"立即沟通"，发送开场白。开场白针对 JD 写一到两句：点出自己与该岗位最相关的一条经历或技能，别用"你好，我对这个职位很感兴趣"这种空话。用户提供了模板就用模板加一句定制。
3. 每发一个间隔 10-30 秒，模拟人的节奏。单次批量不超过 20 个；平台提示今日沟通次数达上限时立即停止并报告进度。
4. 每投一个在台账记一行。

页面弹出异常提示（操作频繁、账号异常、需要验证）时立即停下报告，不要换姿势重试。

## 第四步：消息回复（半自动）

打开消息列表，逐条分类处理。原则：**每条回复都先给用户看草稿，确认后再发**。完全无人值守的自动回复不做——风控风险和错发成本都太高。用户如果预先批准了某类消息的固定回复模板（如"求简历就发"），发送前仍列出这次要发给谁。

- 招聘者主动问候：起草回复，带上与对方岗位匹配的一句亮点。
- 索要简历：经确认后点发送在线简历/附件简历。发附件前报文件名。
- 约面试：整理出时间、形式、地点/链接给用户拍板，用户定了再回复确认。面试安排永远由用户决定。
- 明显不合适（岗位不符、猎头群发）：汇总成一组报告用户，问是否统一婉拒或不回。
- 对方要求加微信、线下付费、培训贷、交押金：诈骗信号，标记提醒用户，不代回。

## 投递台账

在材料文件夹维护 `applied-log.csv`：日期、公司、岗位、薪资、状态（已打招呼/已发简历/约面/婉拒/无回复）、职位链接、备注。每次会话开始先读台账，避免重复投递；每次会话结束更新状态。

## 红线

- 不代用户接受 offer、答应到岗时间、承诺薪资期望之外的条件——这些只整理信息给用户决定。
- 不用脚本注入或接口调用模拟操作，只通过浏览器正常界面动作。
- 不同时开多个自动化会话刷投递量。
- 保护隐私：台账和画像文件不写身份证号、密码；聊天记录里对方的联系方式只在用户要求时摘录。

## 结束报告

汇报：本次投了几个（列公司岗位）、回复了几条消息、新收到的重要消息（约面试的置顶）、台账更新情况、下次建议的动作。
